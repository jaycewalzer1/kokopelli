## P4-E: heat, memory and power guards in the queue

`ops/gpu.py`:
- A job at the head of the line also waits while macmon reads the GPU at 95 °C or more (`KOKOPELLI_GPU_HOT_C`). No reading never holds a job.
- `run` without `--gb` takes the last successful, non-dry run of the same `--name`'s `peak_job_gb` from the ledger, plus 10%. `--gb 0` still means no hold; dry runs default to 0. Prints the default it chose. Example: `wmmc_a4_full_8bit` → 30.9.
- `status` prints `warning: ...` first when `pmset` shows Low Power Mode or battery power (the cause of the 1,782 s paint). Nothing printed on AC, so `idle` stays `idle`.
- `ops/tests/test_gpu.py`: +3 (`Guards`: hot GPU holds then releases; `--gb` default incl. failed/dry/other-name rows ignored and explicit 0; status warning on battery and Low Power Mode). Existing tests now point macmon and pmset at missing paths, so the real machine's heat and power can't leak into them. 19 → 22 OK.

Effect, from the ledger: 8 of 25 jobs with readings reached ≥ 95 °C (`commons_*`, `exp1_T8_pilot10`, `fable_p3c_still_B`). The hold only delays a job's start; it can't cool a job that heats itself. No before/after speed number: this is a guard, not a speed change.

Live check on this Mac (AC, High Power): `status` prints no warning; GPU read 74 °C during `fable_p3c_still_A300`.
