## P2-B Root modules into `core/` with shims (2026-11-09)

**What changed.**
- `git mv` of the 12 root modules (`settings blend llm_model world_model edges world_filter world_transfer world_transfer_multi world_multicontrol_base world_stream world_stream_multi ram_share`) into `core/`, plus an import-free `core/__init__.py`. The rename is its own commit (dad5e31) so `git log --follow` keeps history.
- Intra-core imports now name the package: `from core.settings import ...` (llm_model, world_model), `from core import world_transfer as wt` (world_transfer_multi, world_stream, world_stream_multi), `from core.world_transfer import ...` (world_multicontrol_base), `from core.world_stream import Worker` (world_stream_multi).
- Every `ROOT = Path(__file__).resolve().parent` in core became `.parent.parent`, so `ROOT` is still the repo root (settings, ram_share, world_transfer, world_transfer_multi, world_multicontrol_base, world_stream, world_stream_multi). `world_filter --model-dir` default and `world_model`'s path to `world_filter.py` got the same fix.
- Subprocess command lines that used to run `Path(__file__)` now run `ROOT / "<name>.py"`, the root shim. The command string is byte-for-byte what it was before (same absolute path), and `sys.path[0]` stays the repo root for the Cosmos-venv worker.
- Root shims (12 files). Deviation from the plan, on purpose: instead of `from core.x import *` plus re-exports, each shim does `import core.x; sys.modules[__name__] = core.x`. `import ram_share` then returns the very same module object as `core.ram_share`, so private names (`ram_share._LIBPROC`, used by `ops/memguard.py`/`ops/gpu.py`), `mock.patch("settings.X")` and `mock.patch.object(world_transfer, ...)` all reach the real code. A star-import shim would silently break patching (tests would patch the shim's copy while core code reads its own globals). The 7 modules with a `__main__` block run `runpy.run_module("core.x", run_name="__main__")` when started as a script; `alter_sys` is left off so `sys.argv[0]` and argparse's `prog` stay `ram_share.py` etc. None of these modules use pickle, multiprocessing or `sys.modules["__main__"]`, so not swapping `__main__` is safe.
