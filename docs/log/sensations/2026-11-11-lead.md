  "Qwen3-VL-8B 4-bit". The videos (`egg_wm.py`) do decide with the 4-bit weights. I corrected the two `--about` texts and
  left the behaviour alone. Tonight both get run: `evals_hunger_egg_base` (full weights, the plan's job name) and
  `evals_hunger_egg_base4bit` (what the videos use, and what a 4-bit LoRA has to be read against).
- **At "full", the video's first two decisions carry no cue at all.** Mild bands come and go in a live run, and "full" (food
  92) is a mild band: shown at decisions 2, 3, 6 of the first 8, not at 0 or 1. "half" shows at 0, 3, 7. "starving" always.
  So the full-level film's answer to the ask is a no-body answer. Nothing changed; see Decisions.
- **Worktrees import the main checkout's code unless the worktree root comes first on `sys.path`.** The shared `.venv` has
  the library installed editable from `~/Desktop/kokopelli`, and that puts the main checkout's root on the path.
  `python -m ...` from the worktree root and `test_all.sh` are fine (the current folder wins). `.venv/bin/python some/script.py`

## Decisions for Jayce

1. **Shared files edited on this branch:** `pyproject.toml` (layers contract, new contract, `testpaths`), `tools/fable/test_all.sh`
   (one path), `AGENTS.md` (the area row with new paths, `body/` and `sensation/` in the layout bullets), the top `README.md`,
   and one row each in `kokopelli/agents/README.md` and `kokopelli/life/README.md`. No area in AGENTS.md owns these. The plan
   allowed writing the diff in the log instead; I edited them on the branch because the gates can't be measured otherwise and
   nothing reaches `main` without you. Option: revert any of them at merge time.
2. **Where `body` sits in the layers.** The plan put it between `mind` and `wm`. I also forbade it from importing `wm` at all
   (the fourth contract). Tradeoff: stricter than asked, so a future body module that wants a world-model helper has to move
   the helper or change the contract; in return a sweep can never pull a model in through `body`.
3. **Merge instead of rebase.** Keeps the milestone branch's commits and needs no force-push. A rebase would give a straight
   line but rewrites four commits that are already on GitHub.

4. **Which precision is "base Qwen" for the sensation sweeps?** Options: (a) full weights, the benchmarks area's base, so
   sensation results sit beside the other instruments; (b) 4-bit, the model that actually lives in the videos and the one a
   Mac-trained LoRA starts from; (c) both, always (twice the GPU time, and you learn whether quantization moves the verdict).
   Tonight is (c).
5. **Should a mild cue be allowed to be absent at the moment of the ask in the videos?** Options: (a) leave it: it is how the
   live loop is meant to feel, and the sweep (where every sample sees the cue) carries the statistics; (b) always show the
   cue on the decision that answers the ask, so the three films differ in the body at the moment that matters; (c) pick a
   seed where full shows at decision 0. (b) and (c) change a prompt, so not tonight.

6. **Kokoro needs GPL-3.0 packages to speak** (`phonemizer-fork`, `espeakng-loader`), plus 47 others including torch, in
   whichever environment runs it. Options: (a) install into the shared `.venv` (simplest; puts torch and GPL code beside
   everything else); (b) a separate voice venv called as a subprocess (keeps the main one clean; one more environment);
   (c) a different TTS with no GPL parts; (d) drop the voice. Then merge `sens/voice`. Lane F's log has the detail.
