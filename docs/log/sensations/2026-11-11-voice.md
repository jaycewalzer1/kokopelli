## 2. What `mlx-audio` 0.6.4 needs for `lang_code="a"`, and what the shared `.venv` has

Read from the installed source, nothing imported or run:

- `mlx_audio/tts/models/kokoro/kokoro.py:295` `generate()` builds a `KokoroPipeline` for the language.
- `mlx_audio/tts/models/kokoro/pipeline.py:137-141`: for `a` and `b` it imports **`misaki.en` and `misaki.espeak`**, both
  outside the `try`. If either import fails it raises `ImportError("Kokoro requires the optional 'misaki' package…")`.
  Only *constructing* the espeak fallback is inside the `try`; importing it is not.
- `misaki` is not a dependency of `mlx-audio` (not in its `Requires-Dist`, not in any extra), so `uv.lock` never had it.

`misaki` 0.9.4 (read from its wheel, unpacked for reading only in the scratch folder, sha256 `90e2eeb1…`):

- `misaki/en.py:4,10` imports `num2words` and `spacy` at the top.
- `misaki/en.py:499-501`: `if not spacy.util.is_package("en_core_web_sm"): spacy.cli.download(...)`. **That is a
  `pip install` into the running environment, at the first spoken line.** In the queue job it would install into the shared
  `.venv` unattended (or fail, if the venv has no pip).
- `misaki/espeak.py:1-10` imports `phonemizer` and `espeakng_loader` at the top and points phonemizer at the bundled
  espeak-ng library.

In the shared `.venv` (81 packages): `mlx-audio` 0.6.4, `mlx` 0.32.4, `huggingface-hub` 2.4.0, `scipy`, `miniaudio`,

(`phonemizer-fork`), `espeakng_loader`, `addict`.** No system `espeak` or `espeak-ng` either.
