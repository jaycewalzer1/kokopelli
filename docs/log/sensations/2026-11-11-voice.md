## 3. What changed in `kokopelli/body/voice.py` (no model needed for any of it)

- **It refuses before it downloads.** `kokoro()` now calls `missing()` first (a `find_spec` on each import name in `NEEDS`,
  which imports nothing). If anything is absent it raises `VoiceUnavailable` and the command exits 1 with one line, before
  `load_model` could fetch 355 MB of weights it couldn't use. `en_core_web_sm` is on the list on purpose: with it absent,
  misaki would `pip install` it into the running venv at the first line.
- **`--needs`**: `.venv/bin/python -m kokopelli.body.voice --needs` prints what's missing and exits 1, or exits 0 when
  nothing is. Tonight, in the shared `.venv`: `missing: misaki, num2words, spacy, en_core_web_sm, phonemizer, espeakng_loader`.
- **The revision is pinned.** `REVISION` is the commit above and `kokoro()` passes it to `load_model`, so the sidecar names
  what was loaded, not whatever the repo's `main` is that day.
- **Sidecar.** For a Kokoro track `voice.json` gets `model`, `revision`, `licence` (name, URL, date read, upstream, and
  mlx-audio's licence), `parameters`, `precision`, `voice`, `lang_code`, `mlx_audio` (the installed version). For a
  stand-in it gets `"model": null` and `"stand_in": "a test function spoke, not Kokoro"`, and none of the model's fields.
  If the run's `egg.json` has `dry_run`, `voice.json` copies it.
- **Listen-test proxy.** `check(track, placed, film_seconds, wav=...)`, called by `make()` on every run, result under
  `"check"` in `voice.json` and one line on stdout. Three parts:
  - *duration*: the written wav's own length against the film's, within 0.1 s;
  - *clipping*: the peak and the number of samples beyond full scale, measured on `place()`'s track **before** the clip;
  - *timing*: for each line, where its sound is first heard in the track (the first sample at a tenth of that line's own
    peak) against its decision time. Within 0.5 s is on time. Later than that passes only if the line carries a `delayed`
    reason; a line with no room carries `dropped` and a reason; a line the film's end cut short carries `cut`. Late with
    no reason (for example silence at the front of what the model returned), heard before its decision, or placed but
    silent all fail the check.
- `render()` still exists and still clips; `place()` is the unclipped half of it.
- The docstring said Kokoro and mlx-audio were "both in the main .venv's pins". Only mlx-audio is; it now says so.
- `check()` writes `heard` (where the sound was found) onto each line it was given, so the sidecar's `lines` show it.

Tests: `tests/body/test_voice.py`, 20 tests, all with a stand-in tone, no model. `tools/fable/test_all.sh tests/body`:
43 passed (23 before + 20).

**Not done, and not tested:** the two lines that touch the real model. `load_model(MODEL, revision=REVISION)` is from
reading mlx-audio's source (`tts/utils.py` passes keyword arguments on to the loader, which reads `revision`), and the

## Decisions for Jayce

1. **GPL-3.0 parts in the voice's dependencies.** mlx-audio 0.6.4 can't build Kokoro's English pipeline without importing
   `misaki.espeak`, which imports `phonemizer-fork` (GPL-3.0-or-later) and `espeakng-loader` (bundles espeak-ng,
   GPL-3.0-or-later). They only run as the fallback for words misaki's own dictionary doesn't know. Options:
   (a) accept them as tools we run and don't ship: the audio they help make isn't covered by the GPL, but anything we
   distribute that *includes* them would be; (b) keep the voice out until mlx-audio or misaki makes espeak optional;
   (c) a different TTS: the cache already has `mlx-community/Qwen3-TTS-12Hz-1.7B-*-8bit`, whose licence and
   dependencies I did not read tonight. The voice is viewer-only either way.
2. **Where the voice's packages live.** (a) Add to the shared `.venv` (`pyproject.toml` change below): one environment,
   but 49 more packages including torch 2.15.0 if the whole `misaki[en]` extra is taken. (b) Add only what
   `lang_code="a"` imports (`misaki`, `num2words`, `spacy`, `phonemizer-fork`, `espeakng-loader`, and the
   `en_core_web_sm` wheel by URL so nothing is pip-installed at run time): no torch. I did not dry-run this smaller set.
   (c) A fourth, voice-only environment, with `run_egg_videos.sh` calling it for the voice step: keeps the shared venv
   as it is, costs another environment in `docs/ENVIRONMENTS.md` and a one-line change in the script.
   Proposed `pyproject.toml` change for (b), not applied:

   ```toml
   # dependencies: Kokoro's English text-to-phoneme step (mlx-audio imports these but doesn't declare them)
   "misaki==0.9.4",
   "num2words==0.5.14",
   "spacy==3.8.18",
   "phonemizer-fork==3.3.2",      # GPL-3.0-or-later, see docs/log/sensations/2026-11-11-voice.md
   "espeakng-loader==0.2.4",      # bundles espeak-ng, GPL-3.0-or-later
   "en-core-web-sm @ https://github.com/explosion/spacy-models/releases/download/en_core_web_sm-3.8.0/en_core_web_sm-3.8.0-py3-none-any.whl",
   ```

   The model wheel's URL follows spaCy's release naming; I did not fetch it to confirm it resolves.
3. **A voice track that fails the proxy still gets muxed.** `make()` writes `voice.wav` and records
   `"check": {"passed": false, ...}`; the command prints `FAILED` but exits 0, and the overlay step muxes any `voice.wav`
   it finds. Options: (a) as now: you see and hear the failure, and the sidecar says so; (b) exit non-zero and don't write
   the wav, so a failed track never reaches the panel; (c) write it under another name. (a) is the one that changes
   nothing downstream, so that's what's in.
4. **Timing rule.** A late line passes if it says why (it waited for the previous line). With decisions 15 s apart that
   should be rare, but a long thought can push the next one late by seconds and still "pass". Options: keep; cap the
   wait (drop a line that would start more than N s late); or speak faster when a line would run over.
5. **The dry run isn't on the panel** (section 4). If you want one there as a fixture, the page needs the change in
   section 4 first.
