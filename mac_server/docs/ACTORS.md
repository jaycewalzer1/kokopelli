# SimWorld actor classes (game module `Source/SimWorld`)

Every `/Game/...` prefab path the python client can spawn is redirected to one of these C++
classes by `Config/SimCVRedirects.json` (`/Script/SimWorld.<Class>`). There is no `.umap`
or `.uasset` content: everything is built from `/Engine/BasicShapes` at runtime.
SPEC section numbers refer to `docs/SPEC.md`.

## Classes

| Class | Original prefab(s) | Notes |
|---|---|---|
| `ASWGameMode` | (global default game mode) | Boots the engine's empty `/Engine/Maps/Entry`. In `InitGame` it spawns the `Floor` (4 km slab, top at z=0), sun, sky atmosphere, real-time sky light, height fog and a player start if missing. The player pawn is a `ASpectatorPawn` (camera 0). |
| `ASWProp` | CityDatabase street elements (30 paths) | Static placeholder, pivot at ground centre. Box/cylinder/cone/sphere per asset, flat colour per ue_assets colour group. |
| `ASWBuilding` | `BP_Building_01..126` | Box of the footprint in `bounding_boxes.json`. 57 and 120 have no entry and use the median footprint. |
| `ASWTree` | `BP_Tree1..6` | Trunk (collides) and canopy sphere (no collision) sized from `bounding_boxes.json`. |
| `ASWRoad` | `BP_Road`, `BP_Road1` | Asphalt plus two 20 cm sidewalks, see below. |
| `ASWHumanoid` | `Base_User_Agent`, `BP_Default_Character` | Character with a SimCV camera at eye height. All SPEC 6.1 functions. |
| `ASWPedestrian` | `Base_Pedestrian` | Character, SPEC 6.3 functions. |
| `ASWRobotDog` | `BP_SpotRobot` | Small character with a SimCV camera, SPEC 6.9 functions. |
| `ASWVehicle` | `Vehicle1..5` | Kinematic bicycle model, SPEC 6.2. |
| `ASWEnterableCar` | `BP_VehicleBase_Destruction` | An `ASWVehicle` used by Enter/ExitVehicle. |
| `ASWScooter` | `BP_Scooter_Pawn` | Small `ASWVehicle` with a rider placeholder, `GetOffScooter`. |
| `ASWTrafficLight` | `BP_street_light` | Vehicle + pedestrian heads, timed phases, SPEC 6.4. |
| `ASWPedestrianLight` | `BP_street_light_ped` | Same state machine, pedestrian head only. |
| `ASWUEManager` | `UE_Manager` | `GetInformation`, `UpdateObjects`, `VSetState`, `PSetState`, SPEC 6.6. |
| `ASWWeatherManager` | `BP_WeatherManager` | Sun / fog / atmosphere setters and getters, SPEC 6.7. |
| `ASWMug`, `ASWInteractableBox` | `BP_Mug`, `BP_Interactable_Box` | Pickups (light / heavy). |

Shared code: `ASWCharacterBase` (walking, turning, paths, `EnableController`, `Rotate_Angle`),
`Private/SWCommon.*` (shapes, colours, lookup, JSON), `Private/SWEnvironment.*` (floor, sky),
`Private/SimWorldModule.cpp` (exact-key JSON routes), `USWSettings` (optional mannequin).

## How motion works

Commands only set state and return immediately (SPEC 7.1); `Tick` does the motion.

- Characters use `UCharacterMovementComponent` for gravity, steps and collision, with no controller
  (`bRunPhysicsWithNoController`) and acceleration/braking of 100000 cm/s², so they are at full
  speed or stopped within a frame. Walking `t` seconds at `v` moves about `v·t`.
- Turns (`TurnAround`, `Rotate_Angle`) interpolate yaw linearly and finish in 75 % of the
  requested duration, so the client's equal-length sleep always sees the final yaw.
- Vehicles: `speed' = throttle·500 − 0.5·speed − brake·800` (cm/s², speed ≥ 0, no reverse),
  `yaw' = speed / 280 · tan(steering · 35°)`. Throttle 1 settles at 10 m/s; brake 1 stops from
  there in about 1.3 s. `MakeUTurn` makes the next non-zero steering rotate the car 180° in place at
  60°/s (in the steering's direction) while it creeps forward, then the normal model resumes.
  Scooters: 300 / 0.6 / 600, wheelbase 100, 30° (5 m/s top speed).
- Traffic light phases: `SwitchVehicleFrontGreen` = green `green_s` → yellow `yellow_s` → all red;
  `SetPedestrianWalk` = walk `ped_green_s` → all red. Yellow reports vehicle green = false.

## Choices where SPEC leaves room

- **Prop sizes come from the actor's name.** A redirect maps a path to a class, not to a
  per-asset parameter, so the 161 city paths share four classes. Each prop looks for the
  longest table key that appears as a whole token in its own name (case-insensitive):
  `GEN_BP_Building_64_C_55` → `BP_Building_64`, `GEN_BP_Tree5_3_637` → `BP_Tree5`. That covers
  every `generate_world` node. A prop whose name has no asset in it (`CT_Tree`) gets the class
  default size. The table is `Private/SWPropTable.inl`, generated by `scripts/gen_prop_table.py`.
- **Street element sizes are real-world guesses.** `bounding_boxes.json` gives every element a
  dummy 256 cm cube, which would make soda cans 2.5 m tall. Elements also extend 20 cm below
  their pivot, because progen places them at z=20 (sidewalk height) even where there is no
  sidewalk.
- **Road geometry.** Native size is chosen so that after the node scale (0.95, 0.9, 1) the
  asphalt covers the whole 20000 cm segment, lanes at ±300 cm are on asphalt, sidewalks
  (±1170…±2700 cm, 20 cm high) carry the pedestrian line at ±1700 cm, and the road edge meets
  the building fronts at ±2700 cm (`building_side_distance` 27). Sidewalks stop 2700 cm before each
  segment end so they don't cross the other road at an intersection.
- **Reach** (SPEC choices): seat 150 cm, pickup 200 cm, vehicle 400 cm, scooter 300 cm, all
  measured from the capsule centre to the target's bounding box.
- **Seats** are `Couch` and `BP_Couch` (the catalog has no chairs or benches). `SitDown` and the
  gestures only block movement; there is no animation.
- **`EnterVehicle`** accepts any `ASWVehicle`, not just `BP_VehicleBase_Destruction`. The agent is
  hidden, collision off, attached at the seat. `ExitVehicle` puts it 60 cm off the left side.
- **`GetOnScooter`** destroys the humanoid and shows a rider on the scooter (its walk speed is
  kept). `GetOffScooter` spawns `Base_User_Agent_C_<n>` (first free n) 95 cm to the scooter's
  right, only if someone is riding; otherwise Success is false and nothing spawns.
- **`GetCollisionNum`** counts blocking hits that the agent's own movement reports, sorted by
  the other actor's class (character → Human, vehicle → Vehicle, building → Building, other
  props and pickups → Object; floor, roads and anything stood on are ignored). Repeated hits
  on the same actor count once per second. A kinematic car driving into a standing agent is
  not counted (vehicles move without sweeping).
- **`PSetState "name,state;..."`**: state 0 stops the pedestrian, 1 walks forward, any other
  number walks forward at that speed. Unparseable entries are ignored.
- **`UpdateObjects`** does nothing: `GetInformation` re-scans the world on every call.
- **Weather units.** Sun intensity is the directional light's lux. Fog density is client units
  ×0.001 (20 = engine default 0.02); distance is the fog start distance in cm; falloff is the
  height falloff. Rayleigh and Mie are the sky atmosphere's own scattering scales. Getters
  return exactly what was set (sun yaw normalised to [0, 360)); before any Set they report the
  level's current values.
- **Exact JSON keys.** `GetInformation`, `GetCollisionNum`, `SitDown`, `StandUp`, `PickUp`,
  `DropOff`, `EnterVehicle`, `ExitVehicle` and the four weather getters are also registered as
  dedicated routes (`vbp [str] GetFog`, ...) that write their JSON keys as literal strings.
  The generic vbp path names keys after UFUNCTION parameters, which cannot contain spaces
  (`"Rayleigh Scattering Scale"`), and in non-editor builds FName keeps the first-registered
  casing, so `rotation` could come out as `Rotation`. The UFUNCTIONs still exist for Blueprint
  and for other spellings of the function name.
- **Bodies.** Agents and residents get a skeletal body from `Config/Bodies.json` (`SetBody`/`GetBody`, near/far
  tiers, crossfade, one shared native animation); the cylinder body is only the last-resort placeholder. See
  `city/bodies/ANIMATION.md`. Without Bodies.json the older `CharacterMesh` / `CharacterAnimClass` settings in
  `[/Script/SimWorld.SWSettings]` still apply.
